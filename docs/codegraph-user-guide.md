# CodeGraph 关系图使用说明

在 Code 仓库详情进入“关系图”，先确认顶部的分支、索引提交与更新时间。原“概览与文本查询”和仓库同步入口继续保留。图中展示的是索引快照；同步后需要重新加载，不能继续使用旧节点或旧源码。

## 选择视图

| 视图 | 用途与方向 | 建议入口 |
| --- | --- | --- |
| 调用关系图 | 调用者 → 被调用者，保留递归、自环和平行关系 | 搜索函数或方法，以此为焦点，按方向展开 |
| 潜在影响范围 | 沿反向依赖寻找可能受影响符号；箭头仍保留实际关系方向 | 选择要修改的符号，默认两跳，最多五跳；查看节点的证据路径 |
| 模块依赖 | 依赖方 → 被依赖方；默认目录汇总 imports | 下钻到文件，点击边查看具体声明与源码 |
| 目录聚类总览 | 按目录组织仓库，并逐级进入文件和符号 | 使用目录范围、层级和返回操作；注意边界节点与未加载计数 |
| 继承与实现 | 子类 → 父类、实现类 → 接口 | 选择 class/interface，按父类型或子类型方向展开 |

搜索结果会显示完整路径、类型和行号，便于区分同名符号。选中真实节点可查看签名、位置和同版本源码；目录等聚合节点需要下钻或通过关系证据定位真实源码。证据位于长文件后部时，源码窗会定位到对应行附近，单次最多显示 300 行。

## 阅读聚合与证据

导入数量按“唯一导入声明位置 × 目标文件”统计。同一声明的多个绑定不会重复累加，同一行的不同声明仍分别计数。calls 是独立筛选口径，不与 imports 混算。模块内部依赖计入节点摘要，跨模块依赖计入边；循环依赖会列出实际组成边。

在符号层，同一个声明可能连接多个真实符号，所有实际目标都会保留。跨目录、文件、符号层级对账时使用界面显示的唯一证据总数，不把符号层每条边的计数相加。

聚类下钻保留范围外的入向和出向连接，以边界节点展示。目录、文件与符号层的总数请看“唯一声明/调用点”，接口字段为 `aggregation.distinctSiteCount`。符号层会保留同一声明连接的不同真实符号，例如一次导入同时引入两个函数会显示两条关系；这两条边共享一个声明，不能把符号边上的数量直接相加作为唯一声明总数。比较不同层级时，应保持范围与关系类型一致。折叠余项代表未展开的成员，可搜索具体符号或缩小范围继续查看。

继续加载时展示的是已扫描累计计数。看到“部分结果”或截断提示时，可继续加载；没有继续加载入口时，需要缩小范围或选择更细的文件层级。未完成扫描时没有显示循环，不代表仓库没有循环。外部和未解析目标没有可验证的目标源码。

图形操作包括定位、缩放、适应画布、焦点切换和撤销展开。也可以切换到关系列表，通过键盘选择节点、查看关系和源码。窄屏使用收起的搜索与详情面板。

## 能力和状态

当前适配 SDK 1.6.2 的 TypeScript、JavaScript 和 Java 静态索引。Java 支持浏览方法调用、类继承、类实现接口、接口继承，以及导入声明的依赖和目录聚类证据。搜索到 Java 包（namespace）时，可继续选择其中的方法或类型；包本身没有调用或继承关系，空结果不表示 Java 语言不支持。类、字段中的初始化调用也可能由 SDK 记录在对应节点上。

Java 图只展示 SDK 已提取且通过适配器筛查的关系。接口派发等推断边、无法核实目标的调用，以及部分动态调用、反射和星号导入相关调用会被省略，界面会显示相应限制提示。导入聚合使用可核对的声明位置，并能通过证据查看同一索引版本的源码。Java 支持不代表完整 Java 语义解析，也不保证所有调用都会出现在图中。

TypeScript/JavaScript 保留原有提取行为。类继承和类实现接口可用；SDK 1.6.2 未提取测试中的 TypeScript 接口继承，因此接口向父级的查询会提示不支持。导入视图也可能缺少星号再导出等关系。“索引扫描完成”不等于源码或运行时关系完整。

潜在影响沿已展示的调用、导入、继承、实现和引用关系反向查询，当前不包含对象实例化（instantiates）关系。被省略或未提取的边也不会进入影响路径；结果只能提示潜在影响，不能直接推断运行时一定受影响。目录聚类按路径分组，不代表系统自动识别了业务架构。

无索引时先同步；构建中等待完成；失败时查看仓库错误并重新同步。无权限需要具有资产读权限和所属团队成员身份。版本失效后重新加载；若工作树源码已改变而索引未更新，需要重新同步，不能用旧边对应新源码。
